# 隐私政策

**Apnea Comp**

*最后更新: 2026年9月18日*

---


## 1. 简介

本隐私政策说明 **Apnea Comp** 移动应用程序（以下简称"我们"、"本应用"）在您使用我们的服务时如何收集、使用和保护信息。本应用是一款大会管理工具，专为参加 AIDA 认证大会的自由潜水赛事组织者、裁判、工作人员和运动员而设计。

使用本应用即表示您同意本政策中所述的处理方式。

---


## 2. 我们收集的信息

### 2.1 账户信息

当您创建账户时，我们会收集：

- **电子邮件地址** — 用于身份验证和账户恢复
- **显示名称（Display name）** — 向同一赛事的其他参与者显示
- **密码** — 通过我们的身份验证提供商（Supabase Auth）以安全哈希形式存储。我们绝不以明文存储密码。


**使用 Apple 或 Google 登录。** 您可以使用您的 Apple 或 Google 账户登录，而不使用电子邮件加密码的登录方式。当您这样做时，我们会从 Apple 或 Google 接收您的**姓名**和**电子邮件地址**，以创建或识别您的账户。如果您使用 **Sign in with Apple** 并选择隐藏您的电子邮件，Apple 会向我们提供一个私密中继电子邮件地址，而非您的真实地址，我们对其的使用方式与任何其他电子邮件相同。我们绝不会接收您的 Apple 或 Google 密码 — 登录由该提供商与我们的身份验证提供商（Supabase Auth）共同处理。


### 2.2 个人资料信息（可选）

- **个人资料图片** — 如果您选择上传。该图片对您加入的任何赛事的其他成员可见，并在活动日志中被引用（见第 2.6 节）。

### 2.3 运动员账户关联（针对运动员）

如果您注册为运动员以查看出发名单和您本人的成绩，本应用将存储：

- **AIDA 运动员 UUID** — 来自 AIDA International 的永久标识符，用于将您的账户与您在赛事 Start List 中的出场记录进行匹配。仅在赛事组织者的邀请码经过验证，或您的姓名与赛事 Start List 匹配并获得批准之后，该 UUID 才会与您的账户关联。
- **同步的显示名称** — 您在 AIDA Start List 中公布的姓和名（First/Last name），在关联步骤中复制到您的个人资料
- **AIDA 搜索查询** — 当您使用"在AIDA中查找"（Find me on AIDA）功能查找您的运动员资料时，您输入的姓名会被发送到 AIDA International 的公开运动员搜索服务，以检索匹配的资料。仅传输您输入的文本；不包含任何账户凭据（见第 4.1 节）。
- **AIDA 公开资料查询** — 当任何人在本应用中打开某位运动员的资料时，本应用会使用该运动员的 AIDA UUID，向 AIDA International 网站请求该运动员的公开资料页面和公开成绩页面，并显示 AIDA 在该处公布的职业生涯记录、国家 / 大洲 / 世界排名、参赛历史和资料照片。不会发送任何账户凭据，我们也不会存储副本：查询结果仅在当前会话期间保留在本应用的内存中，并在本应用重启时被丢弃。

此数据仅保留在您本人的个人资料中，用于为您参加的赛事启用只读访问。

### 2.4 运动员比赛数据（从 AIDA 加载）

当赛事组织者从 AIDA International 加载赛事时，本应用将存储：

- **运动员姓名**（姓和名）
- **性别**
- **国籍**
- **项目**（STA、DYN、CWT 等）
- **公布成绩（Announced Performance, AP）**
- **个人最佳成绩（Personal Best, PB）**
- **比赛成绩**（RP、裁判卡片、判罚原因、REMARKS）
- **积分（Points）** — 根据成绩计算得出的大会积分
- **报名类型（Entry type）** — 区分某条报名是常规出发、*opener*（不计入排名且不发送至 AIDA 的热身报名），还是 *re-swim*（经申诉批准的重新表现）
- **有效性标志** — 当运动员进行 re-swim 时，原始报名会被标记为 *invalidated*，从而被排除在排名之外；但其仍会显示在 Results 中
- **签到状态** — 运动员处于待签到、已签到、迟到签到还是未出场（DNS），以及签到时间。根据 AIDA 规则，迟到签到或 DNS 会带来比赛处罚；在签到截止时间过后，本应用可能会自动将运动员标记为迟到。本应用在签到时会显示签名板，以便运动员确认出席，但**签名图像本身绝不会被存储** — 仅存储签名已发生这一事实。
- **风险标记（Risk marking）** — 赛事工作人员可对运动员设置的安全标记（见第 2.11 节）

除签到状态和风险标记外，上述信息来源于 **AIDA International 的公开比赛记录**（通过其官方 API）。签到状态和风险标记则直接在本应用内记录。

### 2.5 我们不收集的信息

我们明确**不**收集或存储：

- 运动员的电子邮件地址 — 但拥有本人账户的运动员的电子邮件地址，以及向组织者显示的赛事成员电子邮件地址除外
- 运动员的电话号码 — 但您选择提交的医疗诊断书上所载医生的联系电话除外
- 运动员的实际地址
- 签到签名图像（仅存储布尔标志）
- 用户的位置数据
- 广告或跨应用追踪标识符，以及将您的数据用于广告的任何行为
- 浏览历史
- 您设备中的联系人

我们确实会存储您登录所用设备的一个随机生成的标识符。该标识符由本应用创建，并非源自任何硬件标识符，仅用于确保同一账户在同一时间只在一台设备上登录，以及在赛事期间保持 Speaker Mode 设备的登录状态。

我们不存储运动员的面部照片。您本人上传的个人资料图片会被存储（第 2.2 节）；AIDA International 公布的运动员资料照片，则在资料被打开时由本应用从 AIDA 的公开网站加载并显示（第 2.3 节）。

### 2.6 活动日志

为支持大会期间的运营透明度，本应用会记录在赛事内执行的重要操作：

- **我们记录的内容** — 裁判结果的录入与更正、日程调整（OT Delay）、签到操作（包括系统自动标记迟到）、setup 与出发名单变更、通知的发送与取消、成员角色变更，以及针对运动员医疗诊断书采取的操作（作废、恢复，以及在签到时确认既往黑视）。
- **每条日志条目包含的内容** — 用户的显示名称、个人资料图片 URL（如已设置）、操作类型、受影响的运动员姓名（如适用）、时间戳，以及描述变更内容的结构化明细记录（例如变更前与变更后的成绩值）。
- **独立的判罚审计记录** — 对已保存裁判结果的每一次更改（包括被服务器阻止的尝试）还会另行记录在一张审计表中，其中保存操作用户的电子邮件地址以及更改前后的值。该机制的存在是为了在成绩出现争议时能够还原过程。该表仅对该赛事的 Organizer 和 Main Judge 可读，且在本应用中没有对应界面。
- **可见范围** — 活动日志界面向 Organizer 和 Main Judge 开放。日志条目存储在赛事内部，在技术上可由同一赛事中已获批准的成员通过我们的 API 读取。
- **保留期限** — 日志条目与判罚审计记录会在赛事记录存在期间一直保留。它们并未通过数据库约束与赛事关联，因此删除赛事不会自动移除它们；参见第 5 节。

### 2.7 推送通知数据

为向您的设备传递与赛事相关的通知，本应用将存储：

- **OneSignal Subscription ID** — 由我们的推送通知提供商（OneSignal）签发的设备专属标识符。仅用作通知的目标地址。
- **OneSignal external user ID** — 您的账户 ID，与 Subscription ID 关联，以便无论使用哪台设备，都能向您的账户发送通知。
- **Subscription 时间戳** — 最后更新时间，用于检测失效的订阅

这些值存储在您的账户个人资料中。当您退出本应用登录时、当另一账户在同一设备上登录时，以及当 OneSignal 报告该订阅不再有效时（例如在本应用被卸载或通知权限被撤销之后），Subscription ID 会被清除。

**注意：** Apnea Comp 此前使用 Firebase Cloud Messaging（FCM）进行推送传递。自 2026 年 5 月起，推送通知基础设施已迁移至 OneSignal。有关所涉第三方提供商的详细信息，请参见第 4.3 节。

### 2.8 设备本地存储

本应用出于两个目的在您的设备上本地存储有限的数据：

**离线缓冲（Judge 结果）**

为在网络连接间歇性中断时（在泳池和深度场地常见）仍能继续操作，本应用可能会在裁判结果到达我们的服务器之前，将其暂时保存在您设备的内存中：

- **位置** — 仅在本应用运行时的内存中。离线缓冲的裁判结果不会写入设备的持久存储。
- **时间** — 在设备离线时尝试保存裁判结果时自动进行。
- **时长** — 直到本应用将结果与我们的服务器同步为止，这会在网络恢复后数秒内自动完成。
- **可见范围** — 离线缓冲的结果仅在创建它们的设备上可见，直到同步成功。同一赛事中的其他设备看不到它们。
- **限制** — 如果在同步完成之前本应用被强制关闭或设备重启，离线缓冲的结果将丢失。本应用会在受影响的项目上显示"⛔ 离线"徽章，并警告用户在项目处于待处理状态时不要退出本应用。

**登录便利（记住邮箱 / 记住密码）**

登录界面提供两个可选开关，可将凭据本地存储，以便在后续登录时预填：

- **记住邮箱（Remember email）** — 如启用，您的电子邮件地址将保存到设备的标准本地存储（Android 上为 SharedPreferences，iOS 上为 NSUserDefaults）。
- **记住密码（Remember password）** — 如启用，您的密码将保存到设备的**安全密钥库**（iOS Keychain / Android EncryptedSharedPreferences，AES-256，由操作系统加密）。它绝不会以明文存储，也绝不会传输到我们的服务器或任何第三方。它仅用于在同一设备上预填登录表单并恢复您的会话。
- **位置** — 仅在您的设备上。此信息不会传输到我们的服务器或任何第三方。
- **如何移除** — 在下次登录时取消勾选该选项、退出本应用（这会清除已存储的凭据），或卸载本应用。

**显示偏好（Display Preferences）**

您的主题选择（浅色 / 深色 / 系统）和应用语言会本地保存（SharedPreferences），以便本应用在每次启动之间记住它们。这些仅为偏好设置，不包含任何个人信息。

离线缓冲、登录便利和显示偏好存储均不会向任何第三方传输数据。

### 2.9 申诉（Protest）数据

当根据 AIDA 大会规则（规则手册 17.7）提交申诉时，本应用会存储一条 protest 记录，其中包含：

- **申诉理由** — 由提交申诉者输入的自由文本
- **运动员签名**以及（如适用）**Jury 签名** — 以手绘图像形式捕获并（以 base64 编码）存储在 protest 记录内。与签到签名板不同，由于已签署的申诉是官方比赛记录的一部分，因此**申诉签名会被保留**。
- **生成的申诉表单** — 一份嵌入了理由和签名的 PDF，存储在我们的后端文件存储（Supabase Storage）中
- **决定与修改** — jury 的决定（accepted / rejected / withdrawn），以及如被接受，修改后的成绩（card、RP、remarks）

**可见范围** — protest 记录对赛事的工作人员（Organizer、Main Judge、Judge）以及该申诉所涉及的运动员可见。申诉活动会触发推送通知（见第 3 节）。

### 2.10 提交的文件（同意书与医疗诊断书）

当运动员加入赛事时，本应用可能会收集并存储组织者所要求的同意及资格相关文件：

- **大会参赛报名表** — 性别、出生日期、出生国家、国籍、各项目的个人最佳成绩，以及**您选择申报的健康相关病史**（最近一次压力损伤/气压伤日期、最近一次黑视日期、最近一次体检日期）。
- **肖像权同意书**与**责任免除同意书** — 您的姓名、赛事名称及地点、签署日期，以及您手绘的签名。
- **医疗诊断书（可选）** — 一份包含检查/签发日期以及医生姓名、电话号码和手绘签名的医生适合性诊断书。由于其证明您的健康状况，因此这属于**敏感的健康信息**。医疗诊断书有效期为一年，并可根据您的选择存储在您本人的个人资料中，以便在未来的赛事中重复使用。
- **签名** — 运动员、见证人和医生的签名以手绘图像形式捕获，并嵌入到生成的文件中。与签到签名不同，这些签名会作为同意记录的一部分被**保留**。
- **上传的文件** — 如果您以照片或扫描件的形式提交文件，而非在本应用内填写，则会存储该图像文件。
- **生成的 PDF** — 您在本应用内完成的文件会被渲染为 PDF，并存储在我们的后端文件存储（Supabase Storage）中。

**可见范围** — 提交的赛事文件对该赛事的 Organizer 和 Main Judge 可见以供核验，他们也可以将其批量下载为 ZIP 压缩档。如果您申报了受伤或黑视日期，系统会提示工作人员手动核验您的医疗诊断书。

**提醒** — 如果强制性文件未在赛事前一天之前提交，您可能会收到一条列出缺失文件的推送通知。

**我们为何持有这些信息** — 医疗诊断书以及在大会参赛报名表上申报的健康病史，是基于您在选择填写并提交该表单时给出的**明确同意**而处理的。您可以随时通过第 11 节中的地址联系我们撤回该同意，但此后组织者可能因 AIDA 规则而无法准许您参加比赛。

### 2.11 赛事期间的安全与医疗记录

自由潜水大会对安全高度敏感，AIDA 规则亦要求对特定医疗事件予以记录并采取相应措施。因此本应用会存储：

- **风险标记（Risk marking）** — Organizer、Main Judge、Judge 或 Safety 工作人员可在运动员出场前为其设置的安全标记（none / yellow / orange / red），以便安全潜水员和裁判有所准备。该标记对赛事工作人员在本应用中以及在已配对的 Apple Watch 上可见，并与该运动员的赛事报名记录一同存储。
- **黑视后续处理记录** — 如果运动员发生黑视或被标记为风险升高，Organizer 或 Main Judge 会记录一项后续处理决定（"无异常"或"需重新体检"）、一条可选的医疗备注、决定人以及决定时间。该记录会在同一赛事后续比赛日的签到时再次显示。
- **医疗诊断书作废记录** — 如果需要重新体检，Organizer 或 Main Judge 可以作废您的医疗诊断书。我们会在赛事提交件以及保存到您个人资料的副本上，同时存储作废时间、作废人以及所给出的原因，并通过推送通知告知您。原因本身不会包含在该通知中。同一角色可以撤销该作废。

**我们为何持有这些信息** — 为安全地运营赛事并遵守 AIDA 大会规则。由于这属于健康信息，我们在这项对安全高度敏感的运动中，基于保护运动员和安全工作人员切身重大利益的必要性进行处理，同时也因为您参加 AIDA 赛事时所同意的大会规则对此有所要求。访问权限仅限该赛事的 Organizer 和 Main Judge；风险标记除外 — 与安全相关的工作人员也可查看。这些记录作为赛事记录的一部分保留，并在赛事被删除时删除。

### 2.12 公告与工作人员消息

本应用包含赛事公告板 Board（由 Organizer 或 Main Judge 撰写、赛事内所有人均可阅读的公告）以及 Dispatch（由赛事工作人员发送给选定工作人员的消息）。对于每一条消息，我们会存储其文本、发送者的姓名和电子邮件地址、时间，以及（对于 Dispatch）收件人电子邮件地址列表。当消息以推送通知形式发送时，其文本会原样传递给 OneSignal，且不会被翻译。消息属于赛事的一部分，并在赛事被删除时删除。

### 2.13 排除记录

如果 Organizer 将您从赛事中移除，本应用会保留一条该项排除的记录，以便本应用的自动运动员匹配不会将您重新加入，从而在您不知情的情况下推翻 Organizer 的决定。该记录包含您的电子邮件地址、您的 AIDA 运动员 ID、您姓名的规范化形式、执行排除者、Organizer 输入的任何原因以及时间。即使您不再是该赛事的成员，该记录仍会为该赛事保留，并且不会按计划被移除。Organizer 可通过向您签发新的个人邀请码来推翻该记录。参见第 5 节。

### 2.14 Apple Watch 配套应用

本应用包含一个 Apple Watch 配套应用，可显示 Start List，并在 Apple Watch Ultra 上于您潜入水中时显示包含深度、潜水时间和水温的潜水界面。手表会为此请求"运动与健身"（Motion & Fitness）权限。**深度、水温和潜水时间仅在手表上显示** — 它们不会被发送至手机、我们的服务器、AIDA 或任何其他方，也不会被存储。数据为单向流动：由手机向手表发送赛事名称、您的角色、您的姓名以及 Start List（包括安全风险标记）。

## 3. 我们如何使用信息

我们使用所收集的信息来：

- 验证用户身份并管理账户
- 向获授权的赛事工作人员显示比赛日程和运动员信息
- 向已关联账户的运动员显示 Start List 和个人成绩
- 将裁判结果提交回 AIDA International（在赛事组织者配置后）
- 在赛事工作人员使用的设备之间实时同步数据
- 维护活动日志，以实现赛事内的运营透明度
- 管理根据 AIDA 大会规则提交的申诉，包括捕获签名以及记录 jury 的决定和任何修改后的成绩
- 检查服务器端的最低支持应用版本（一个公开的配置值），以提示用户更新；此检查不传输任何个人数据
- 通过 OneSignal 发送推送通知，包括：
  * **手动通知** — 由赛事组织者触发（出发名单发布、非正式成绩、正式成绩）
  * **自动通知** — 由赛事状态触发（影响特定运动员的日程变更 / OT Delay；向尚未签到的运动员发送的签到截止提醒；申诉活动 — 已提交、等待运动员签名、已决定）；由 Organizer 或 Main Judge 发布的 Board 公告；赛事工作人员发送给您的 Dispatch 消息；文件缺失提醒；以及关于您的医疗诊断书已被作废的通知。Board 和 Dispatch 的文本按撰写原样发送，不会被翻译。
  * 通知文本会本地化为接收者的应用语言，但 Board 和 Dispatch 的消息正文除外
- 记录根据 AIDA 规则运营赛事所必需的安全与医疗信息（见第 2.11 节）
- 保留 Organizer 已从赛事中移除的参与者的记录，以便自动运动员匹配不会将其重新加入（见第 2.13 节）
- 确保同一账户在同一时间只在一台设备上登录

我们**不会**将您的信息用于广告、营销或向第三方出售。

## 4. 数据共享

## 5. 数据保留

- **账户数据** — 在您的账户存在期间保留。删除您的账户会移除您的登录凭据和您的个人资料（显示名称、个人资料图片、已关联的 AIDA 运动员 UUID、推送订阅和语言设置）。构成赛事官方比赛记录一部分的记录 — 您的赛事成员资格、成绩、签到、活动日志条目、申诉和已提交的文件 — 是以您使用的电子邮件地址来标识的，不会因删除账户而被移除；它们会按各自的计划被移除（赛事删除，或下文所述的文件保留期限）。如果您希望更早移除这些记录，请通过第 11 节中的地址联系我们。
- **赛事数据**（运动员、成绩、签到状态、申诉、文件、公告与工作人员消息、黑视后续处理记录） — 在赛事组织者删除赛事时自动删除。
- **活动日志与判罚审计记录** — 在赛事记录存续期间保留。它们并未通过数据库约束与赛事关联，因此删除赛事不会自动移除它们；如需移除，请通过第 11 节中的地址联系我们。
- **排除记录** — 如果 Organizer 将您从赛事中移除，我们会保留一条该项排除的记录（您的电子邮件地址、您的 AIDA 运动员 ID 和一个姓名键、执行移除者以及所给出的任何原因），以便自动重新注册不会推翻 Organizer 的决定。该记录将无限期保留，且只能由该 Organizer 签发新的个人邀请码来推翻。
- **批量下载压缩档** — 当 Organizer 或 Main Judge 将某一赛事的全部文件或申诉表单批量下载为 ZIP 时，该压缩档会被写入我们的文件存储，并通过一个 10 分钟后过期的链接共享。文件压缩档会在一天后删除；申诉压缩档会在 30 天后删除。
- **申诉数据**（理由、签名、决定） — 作为赛事的一部分保留，并在组织者删除赛事时随赛事一同删除。存储在我们文件存储中的生成的申诉 PDF 会在单条申诉被删除时移除，并且在任何情况下都会**在生成 30 天后自动删除**。protest 记录本身 — 包括理由、决定和已存储的签名 — 则不设时限，会在 PDF 被删除之后继续保留，直至赛事被删除。
- **提交的文件**（大会参赛报名表、肖像权同意书、责任免除同意书，以及提交至赛事的医疗诊断书） — 作为赛事的一部分保留，并在**赛事结束 15 天后自动删除**。您保存到本人个人资料中的医疗诊断书会在其一年有效期内保留，并可随时撤回。
- **OneSignal Subscription ID** — 在您退出本应用登录时、另一账户在同一设备上登录时，或 OneSignal 下一次报告该订阅不再可达时（例如在本应用被卸载或通知权限被撤销之后）被清除。在此之前，该标识符会一直存储在您的个人资料中。
- **本地存储的凭据**（记住邮箱 / 记住密码） — 保留在您的设备上，直到您禁用该选项、退出登录或卸载本应用。
- **离线缓冲的结果** — 仅保留在设备内存中；在网络恢复后数秒内同步到我们的服务器，或在同步前本应用被关闭时丢失。
- **身份验证令牌** — 短期有效；自动刷新或过期。

## 6. 数据安全

我们通过多层安全措施保护您的信息：

### 传输与存储

- 所有数据均通过加密的 HTTPS 连接传输
- 数据由我们的基础设施提供商（Supabase）静态加密
- 密码使用行业标准算法进行哈希处理；我们绝不存储明文密码

### 数据库级访问控制

- 在包含用户或赛事数据的所有表上，于数据库级别强制执行 **Row-Level Security（RLS）**
- 用户只能访问其所属赛事的数据
- 待批准或未批准的成员无法访问赛事数据
- 权限在每次查询时都会检查，而不仅是在登录时

### 基于角色的权限

- **Organizer / Main Judge** — 可管理赛事、成员和比赛数据；查看活动日志；核验已提交的文件；记录黑视后续处理决定；发送手动推送通知。Organizer 可以以 **Observer** 身份加入，此身份会将其从赛事成员列表中隐藏，但授予相同的权限。
- **Judge** — 可查看和提交比赛成绩、设置风险标记，以及查看申诉
- **Safety** — 可查看赛事数据并设置风险标记
- **Photo** — 可查看 Start List，并记录其被指派拍摄哪些运动员
- **Staff** — 可查看赛事数据
- **Athlete** — 对 Start List、本人比赛成绩、本人已提交的文件以及与其相关的申诉的只读访问
- 权限按赛事范围隔离；某一赛事中的裁判无权访问另一赛事

### AIDA API 令牌保护

- 用于与 AIDA International 同步的 AIDA API 令牌保存在一张独立的、已锁定的数据库表中，任何应用角色都无法直接读取或写入：默认拒绝一切访问，仅通过受限的服务器端函数授予访问。它们与其他所有数据一样，由我们的基础设施提供商静态加密。
- 只有 main_judge 和 organizer 角色才能检索令牌，并通过受限的数据库函数强制执行
- 其他角色（judge、staff、athlete）即使有权访问其他赛事数据，也无法访问令牌
- 令牌在用户界面中被遮蔽；用户必须明确选择才能显示它们

### 会话与访问

- 身份验证令牌为短期有效，并自动刷新
- 当用户从赛事中被移除时，访问权限会被实时撤销
- 账户凭据由您负责；切勿共享它们

虽然我们采取合理措施来保护您的信息，但没有任何系统是完全安全的。您有责任对您的账户凭据保密，并报告任何可疑活动。
